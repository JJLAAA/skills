Handoff 驱动的 Agent 接力流程

handoff 文件不是人类摘要，而是 target agent 的任务入口：保留事实和关键决策，更新路由与下一步动作，让 source agent 与 target agent 通过共享工作记忆持续协作。

启动 写入 执行 接力 恢复
1 触发与澄清
ASource Agent 启动 handoff
用户说 handoff / 保存进度 / 交接，或上下文接近限制。
默认文件名：YYMMDD-handoff.md，除非用户指定路径。
?先确定路由
明确 Target reader：Codex / Claude Code / next AI agent。
明确 Execution type：继续实现 / review / debug / 架构判断。
任一字段不能推断时，只问一个覆盖两者的澄清问题。
2 生成自举任务包
0Handoff Routing
写清 target agent 的身份、执行类型、期望行为和边界。
加入 How to read this handoff：先读 routing，再执行 first action。
若从上一棒改派，必须写 Reroute reason。
M共享工作记忆
保留目标、进度、关键上下文、重要决策。
记录 findings、失败方案、风险、文件清单、git 状态。
写入精确路径、函数、命令和验证结果。
3 Target Agent 执行
B只按文件启动
把 handoff 当任务入口，不依赖聊天上下文。
先执行 Next Agent's First Action，再扩展探索。
不要把 review 任务扩大成重构，或把 debug 任务扩大成架构设计。
✓产出结论
按 execution type 产出：findings / 修复 / debug 结论 / 架构判断。
验证命令和证据写回状态，而不是只写结论。
如果需要下一棒，准备接力更新。
4 接力更新
K保留稳定内容
保留事实、决策、review findings、失败尝试、验证结果。
保留文件清单和 git 状态，作为下一棒的可执行证据。
不要默认把 handoff 覆盖成全新总结。
N只更新下一步协议
更新 target reader、execution type、expected behavior、out of scope。
更新 current progress、pending tasks、recommended first steps。
切换 target 或执行类型时，写明 reroute reason。
5 下一棒恢复
R读取最近 handoff
新 session 检查 *-handoff.md，读取最新文件。
展示摘要：任务、execution type、进度、下一步。
用户确认后，按 Recommended First Steps 恢复上下文。
∞持续异步协作
source agent 与 target agent 通过文件交换状态。
人类只负责投递文件、决定下一棒和验收。
完成后可删除 handoff，未完成则继续接力。

1核心不变量

handoff 是给下一位 AI agent 的技术交接，不是给用户看的摘要。它必须包含可执行上下文：路径、函数、命令、验证状态、失败尝试和决策理由。

stable memory = facts + decisions + evidence + failed attempts

2接力更新原则

同一任务继续推进时，保留工作日志和关键结论；只更新路由、当前进度、待办和 next action。换目标或换执行类型时，必须写明改派原因。

update = routing + progress + pending tasks + first action

3边界控制

Target agent 先确认自己的角色，再执行指定动作；不要扩大任务范围。review 就输出 findings，debug 就定位根因，implementation 就做最小修复和验证。

agent behavior follows Target reader + Execution type
